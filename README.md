## 저는 이번 미션에서 3가지에 집중했어요.

### 1. '고민없이 바로 행동 가능한' ToDoList를 만들기

- 총 4번 투두리스트를 갈아 엎었지만, 막상 개발을 해보니까 투두리스트의 작업단위가 쌓일수록, 이전에 완료한 투두리스트의 코드를 수정해야하는 문제가 있었습니다.
- 어떻게 작업 단위끼리 영향을 주지 않고 전진 개발을 하게 요구사항을 정리할 수 있을까? 고민이 듭니다.
- 이 부분을 더 고민하고 싶었는데, 벌써 1주차가 종료가 돼서 고민-해결-리팩토링 단계로 이어지지 못했습니다.

### 2. System.exit()로부터 어떻게 더 잘 종료할수 있을지 학습한 경험

빈 문자열이면 0을 출력 후 종료해야하는 요구사항으로부터 System.exit()를 사용했었지만 요구사항에서는 금지하고 있었습니다. 편리한데 왜 금지하지?
그 금지를 유발하는 원인을 극복하는 다른 방법들은 무엇이 있을까? 이런 질문을 던지며 main 함수 종료 방법을 학습한 경험을 했습니다.

### 3. 정규식 컴파일을 어떻게 더 잘 활용할 수 있을지 가설-실험으로 검증하여 답을 내본 경험

저는 정규식이 문자열 검증/팟싱으로부터 GOD이라고 생각했습니다. 정말 철저하게 검증해주니까요. 그래서 Pattern.compile()을 이용하여 정규식을 사용했고
또한 compile() 내부는 매번 똑같은 컴파일이 매번 재생성 되기 때문에 캐시해야하는 것 까진 알고 있었습니다. CPU 사용량을 줄이기 위해서요.
그런데 딱 1번 사용하는 경우에도 컴파일 비용이 비싸지는 경우가 있지 않을까? 질문을 던지며 어떻게 더 최적화된 정규식을 작성할 수 있을지 가설 -실험을 내려 답을 찾은 경험을 했습니다.

## 문자열 덧셈 계산기 TodoList

### 📌 입력

- [x] 사용자로부터 문자열 입력
  예: "1,2,3" 또는 "//;\n1;2;3"
  ("덧셈할 문자열을 입력해 주세요." 출력)
  (Console.readLine() 사용)

### 📌 처리

- [x] 구분자로 분리하여 숫자 추출 후 덧셈
  쉼표: "1,2,3" --> 6
  콜론: "1:2:3" --> 6
  혼합: "1,2:3" --> 6

- [x] 커스텀 구분자 처리
  "//;\n1;2;3" --> ; 추출 --> {1,2,3} --> 6

- [x] 빈 문자열 처리
  "" --> 0

### 📌 출력

- [x] 계산 결과 출력
  6 --> "결과 : 6"
  ("결과 : {숫자}" 형식)

- [x] 애플리케이션 종료시 총 실행 시간 출력
  (ms 단위)

### 📌 예외 처리

- [x] 음수 입력
  "-1,2,3" --> IllegalArgumentException

- [x] 숫자 아닌 값
  "1,a,3" --> IllegalArgumentException
