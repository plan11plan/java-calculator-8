# 요구사항 정의하기(문제정의)
###  1. 기능 요구사항 TodoList [12분 22초 소요] <br>

>#### 입력
>- 구분자와 양수로 구성된 문자열을 입력받는다.
>- 구성자를 기준으로 숫자들을 추출한다.
>  - 기본 구분자({','와':')
>  - 커스텀 구분자 ( 문자열 앞부분의 "//"와 "\n" 사이에 위치하는 문자를 커스텀 구분자)
>    - 예를 들어 "//;\n1;2;3"과 같이 값을 입력할 경우 커스텀 구분자는 세미콜론(;)이며, 결과 값은 6이 반환되어야 한다.
>- 구분자를 기준으로 숫자들을 분리한다.
>- 사용자가 잘못된 값을 입력할 경우 IllegalArgumentException을 발생시킨 후 애플리케이션은 종료되어야 한다.
>#### 비즈니스 
>- 숫자들을 더한다.
>#### 출력
>- 덧셈 결과를 출력한다.
  

###  2. 비기능 요구사항 TodoList [2분 30초 소요]<br>

>프로그램 종료 시 System.exit()를 호출하지 않는다.
>#### 입력
>- camp.nextstep.edu.missionutils에서 제공하는 Console API를 사용하여 구현해야 한다.
>- 사용자가 입력하는 값은 camp.nextstep.edu.missionutils.Console의 readLine()을 활용한다.
>#### 결과 
>```
>덧셈할 문자열을 입력해 주세요.
>1,2:3
>결과 : 6
>```

### 기능 요구사항을 작성하면서 어려웠던 점 

#### 문제 1: 입출력은 기능인가 비기능인가? <br>
```
문제 상황
- 입출력 구현 방법이 기능인지 비기능인지 구분이 어려웠다
- "구분자로 입력받는다"와 "파싱 방법"의 차이가 모호했다

나의 행동
- 입출력이 없으면 동작 자체가 안되니까 입력/비즈니스/출력으로 3분할 했다. 

결과
- 일단 정리는 완료했다.
- 근데 확신하기 어렵다.

받고 싶은 피드백
- 입출력을 어떻게 구현하는지도 구현에 넣어야하는가? 
  이거를 고민하는 이유가, 입출력에서 제대로 팟싱이 안되면 애플리케이션이 안돌아가기 때문이다. 
```

#### 문제 2:  예외처리는 최소 동작 애플리케이션에 포함 되는가?
```
문제 상황
- 예외처리가 명시적으로 적힌 요구사항인데 MVP에 포함인지 기준이 안선다. 
  해피케이스만 생각하면 일단 앱이 돌아가기 때문이다. 예외처리까지 MVP에 포함시켜야하는가?

나의 행동
- 예외처리를 기능 요구사항에 포함
- 하지만 구현 순서에 대한 확신이 없다.

결과
- 일단 MVP에 예외처리를 넣었다.
- MVP 범위가 모호해졌다.

받고 싶은 피드백
- MVP는 happy case만 고려하나?
- 나는 요구사항을 기능/비기능으로 나눈게 맞는가? 
  맞다면 나는 기능/비기능을 어떻게 더 잘 나눌 수있지?
```

#### 문제 3: 내가 작성한 TodoList는 무엇부터 개발하면 좋을지 불명확하다.
```
문제 상황
- 요구사항으로부터 기능 요구사항으로 부터 ToDoList를 작성해야 한다.

나의 행동
- 시스템은 What 무엇을 하면 되는가 행동 중심으로 정리했다.
- 하지만 구현 순서에 대한 확신이 없다.

결과
- TodoList를 보고 개발자가 바로 개발하기엔 우선순위 불명확하다.

받고 싶은 피드백
- 어떻게 하면 개발자가 바로 행동으로 옮길 수 있는 TodoList를 만들 수 있을까?
```
